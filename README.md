# Levitation

Levitation 是一个贴在屏幕边缘的 Windows 待办悬浮窗。工作时把鼠标移到屏幕右侧，就能快速查看或勾选待办，无需切换当前窗口。鼠标移开后，悬浮窗自动收起。

同一个浮窗也能收纳常用文件、文件夹、文本、链接和截图，随手打开文件或复制文本，方便继续手头的工作。

**[下载 Windows x64 预览版](https://github.com/HysenX-LI/Levitation/releases)**

## 使用

下载或构建自带运行库的 Windows x64 压缩包，解压后运行 `Levitation.exe`，无需另装 .NET。

- 默认收纳在选定显示器工作区的右侧；鼠标移到窄入口时展开。
- 拖动主窗口顶部可自由移动。明显向右拖动至少 56 个逻辑像素、横向移动占主导，且预期右边缘越过显示器边缘 20 个逻辑像素时，会缩成右侧入口预览。保持按住同一次鼠标操作，就能继续上下定位入口；松手保存，Esc 取消。普通上下拖动只移动完整窗口，鼠标离开后仍可自动收起。
- 入口可从右上方拖到右下方；展开窗口以入口中心对齐，遇到上下边界时保留 12 个逻辑像素边距。靠上时顶边固定，往下拖到足够位置后再下移。位置和窗口模式按比例持久化，适应屏幕大小及缩放变化。
- 鼠标离开后默认等待 0.5 秒收起。设置可调整为 0.2～30 秒；已有自定义时间继续保留。正在打字、拖动、拉伸、打开菜单或待办／卡片编辑窗口时暂停自动收起，操作结束后恢复。设置窗口独立打开，不阻止浮窗正常自动收起。空输入框残留焦点或未提交的草稿不再无限阻挡收起，草稿会保留。
- 自动收起保留鼠标容错区：停靠展开时，右侧空隙一直覆盖到当前屏幕工作区的右边缘，左侧额外 8 像素、上下额外 16 像素；自由浮动时右侧额外 24 像素，不扩大到整片桌面。仅影响收起判断，不改变窗口外观或拦截空隙中的鼠标操作。动画中沿用展开位置的同一容错区，避免侧边触发位置反复收起、展开；进入相邻屏幕后不继续占用容错区。
- 浮窗底边的把手可上下调整高度，左边的把手可左右调整宽度，左下角可同时调整宽高。拖动时对侧边缘保持固定，显示器空间足够时宽度可在 280～640 逻辑像素间调整。把手贴边且不占内容空间。松手后保存，Esc 取消，重启后保留。初始高度随显示器可用高度调整；已完成区域随窗口高度调整，超出部分在内部滚动。
- 侧边入口为较长的半透明细条，不显示勾或数字。展开／收起使用约 200 毫秒的缩放、移动与淡入淡出，快速返回时可反向衔接；系统关闭界面动画时直接切换。
- 深浅主题覆盖主窗、设置与编辑窗口的背景和文字；保存设置或导出备份成功后不弹窗。
- 待办可勾选完成、取消完成、双击或右键编辑、删除。未完成在上，当天完成在下。条目采用单行省略显示。编辑窗口支持填写可选的多行说明：悬停条目时显示待办标题，有说明时在细分隔线下方显示说明。提示跟随深浅主题并自动换行，超长内容可在编辑窗口查看。说明随待办保存，完成、删除恢复、备份及重启后保留。旧待办默认没有说明，无需迁移。直接按住未完成条目的文字或行内空白区域可拖动排序，没有拖动把手；勾选框和删除按钮独立处理点击，双击文字区域仍可编辑。拖起的行跟随鼠标，其他行连续平滑让位，靠近列表边缘可继续滚动，也可用滚轮。松手立即保存一次，约 85 毫秒落位动画独立播放，不阻挡下一次点击顺序；Esc、失去鼠标捕获或窗口失活时取消，拖动过程中不写入数据。右键也能上移／下移。顺序重启保留，完成历史不变。
- 每条待办支持“未开始／正在做／已暂停”。右侧播放按钮开始；进行中时左侧变为缓慢旋转的细圆环，右侧显示完成和暂停；暂停后圆环静止并显示暂停标记，右侧可继续。左侧圆环和右侧勾都能完成，未开始时仍可直接点左侧方框完成。完成后只显示勾线，撤销完成回到未开始。各条待办可以独立开始，不强制互相暂停；这些操作不改变排序、说明或已有完成记录。
- 开始／暂停状态随待办持久化，重启、删除恢复和备份恢复后保留；旧数据默认未开始，每一天新生成的重复任务独立从未开始起步。完成状态仍由原有完成时间与历史管理，不另建第二套完成记录。动画不写入数据，在窗口隐藏、卡片折叠或控件卸载时停止；系统关闭界面动画时保留静止圆环，通过右侧按钮和暂停标记区分状态。
- 待办行左侧为 4 像素留白，再放置 16 像素状态标记和 8 像素间隔；今日已完成的箭头、勾和文字同步对齐。右侧四个按钮位置固定，开始、暂停、继续时不会左右跳动；直接拖动文字排序与双击编辑保留，状态按钮独立响应点击。
- 待办最多支持三层子待办（主待办 → 子待办 → 二级子待办 → 三级子待办）：垃圾桶左侧的加号控制添加框显隐，输入后按 Enter 或点回车图标保存，Esc 收起添加框。单击父待办文字或行内空白展开／折叠；折叠时同步收起添加框，再展开只显示已保存的子项，需要继续添加时再点加号。输入草稿在本次运行内保留，重启默认折叠、添加框隐藏。展开／收起有短暂高度过渡，系统关闭动画时直接切换。
- 子待办缩进显示，可独立勾选、删除，双击或右键编辑；父项旁显示已完成／总数，窄窗口自动隐藏数量。父项拖动时携带整组子项；全部子项勾完不会自动完成父项，父项开始、暂停或完成也不修改子项勾选。已完成父项可展开查看和调整现有子项，不提供新增入口。日常任务每天新生成的待办不复制上一天的子项。
- 所有子待办也可直接按住文字行拖动，保留单击折叠、双击编辑，状态与操作按钮单独响应。同级可排序，主待办可拖入另一条成为子待办，子待办可跨父项移动，也可拖到主待办前后成为独立待办；带有下级的条目携带整组一起移动。靠近目标行上／下边缘显示前／后插入线，行中部显示归入高亮；归入提示立即显示，已展开目标和空目标立即预留位置；折叠且已有子项的目标悬停约 160 毫秒后展开，直接松手也可放入。拖起的行跟随鼠标，其他条目使用跟随屏幕刷新的临界阻尼过渡让位，靠近列表边缘自动滚动；松手立即保存一次，约 85 毫秒落位动画独立播放，不阻挡下一次点击，Esc、失去捕获或窗口失活则取消，拖动预览不写入数据。
- 层级按整组计算：目标深度加上拖动分支的最大深度不得超过三层子待办。自身、自己的后代及超深位置均不接受放置，显示禁止光标且不出现放置标记；最深一层不显示新增子项按钮。移动保留 ID、说明、子项顺序、勾选及根待办的开始／暂停信息，移回独立待办后仍可继续原状态。已勾选子项拖成独立待办时保留完成状态，并生成对应完成记录；已完成的主待办仍按完成时间排序，不提供主行拖动，其下子项可调整结构。
- 子待办跟随父项保存、备份、重启和整组删除恢复。单独删除的子项同样计入垃圾堆最近 10 条记录；恢复时回到原父项及原位置，并保留勾选状态。原父项已不存在或原位置超过层级上限时恢复为普通未完成待办，恢复按钮会说明这一行为。旧待办默认没有子项，沿用原数据目录。
- 待办行和常用内容采用按 ID 复用的局部更新，勾选子项仅替换该行并更新父项数量，未变化的条目、图片缩略图及输入框继续使用原控件。连续拖动的让位速度可续接，目标附近有位置判定容差；勾选按钮不再出现外侧按钮焦点框，子项输入框额外左缩进从 28 减为 4 个逻辑像素，保留框内 8 像素边距。
- 默认使用 **Win+W** 打开快速记录：以当前前台窗口所在显示器的工作区为中心，弹出 72 像素高的圆角输入条；整个弹层就是输入框，没有标题、快捷键说明或内层边线。空白时显示“计划做点什么...”，输入后隐藏，右侧仅显示回车线条图标，光标与外框左侧保留 24 像素距离。Enter 保存并收回，再按 Win+W、Esc 或点击外部取消关闭并保留草稿。中文输入法的候选确认不会直接提交待办，保存成功不弹提示。托盘菜单不显示此入口；设置可关闭这个快捷键。
- Win+W 在 Windows 11 原本用于小组件。软件运行且快捷键启用时会占用它；优先使用系统热键注册，遇到系统保留时仅用专用键盘钩子识别 Win+W，不记录按键或文字，不修改系统或注册表设置。关闭此选项或退出软件会释放注册与钩子。启用失败时提示，可在设置中关闭后重新启用。
- 日常任务支持指定日期、每天、每周指定一天或多天。仅指定日期显示月历选择器；每天／每周的新安排从今天开始，编辑同频率的旧安排保留原开始日期。相同名称允许分别添加；同一安排的当天任务只生成一次。
- 每天／每周任务按天独立记录。过去未完成的重复任务不占用今天的主列表；普通待办会一直保留。指定日期任务错过启动日后，会在下次启动时补入。
- 删除一次日常任务只影响本次；删除日常安排时，已生成的待办转为普通待办保留。
- 主浮窗顶部仅显示日期；待办与常用内容各占一个卡片，点击标题可独立折叠／展开并记住状态，草稿与数据保留。两处输入框统一为 30 像素高度、8 像素圆角，保存按钮与输入框等高。常用内容列表只显示名称（未命名时显示内容），不额外显示内容预览。
- 两张卡片底边各有独立的细短高度把手，不额外占用内容行，调整后会保存。待办卡片最小高度可容纳 3 条待办、输入框及完成区标题；常用内容卡片最小高度可容纳 2 条内容和输入框。更多条目在卡片内滚动；整体窗口较矮时可滚动主页面。
- 常用内容点击“保存”或按回车后直接保存，不弹出命名窗口；需要名称时右键编辑。名称与实际内容分开。网址点击打开，复制按钮复制实际内容。右键卡片编辑名称与内容。
- 常用内容支持从 Windows 文件资源管理器拖入一个或多个本地文件、图片和文件夹，保存文件名与完整路径。拖着内容停留在侧边入口约 160 毫秒会展开浮窗，拖到常用内容区域时显示“松开以添加”提示；拖放期间暂停自动收起，放下后恢复。常用内容折叠时也可放到其标题区域，添加后自动展开。重复路径忽略，原文件不移动、不复制，拖放本身不打开文件。
- 也可以从支持拖放的应用选中文字，或从浏览器拖动网页链接、地址栏的网站图标，放到常用内容即可保存。文字保留段落和换行，网页链接保存实际网址，点击卡片时才打开。
- 文件、文件夹使用主题线条图标，JPG／PNG 等图片提供 28 像素缩略图。缩略图在后台按小尺寸解码，同时最多加载两张，读取后关闭文件流；系统不支持的图片编码或读取失败时使用图片图标，仍可点击原文件。这里支持的是已保存在本地、能通过文件拖放提供路径的图片文件，邮件内尚未落地的附件不作为文件链接接收。
- 在常用内容区按 Ctrl+V 或在它的输入框右键粘贴，可以直接保存剪贴板里的截图或图片。图片以 PNG 保存并显示缩略图，点击用默认应用打开。文字和网址仍可粘贴进输入框再保存。
- 粘贴的截图保存在用户数据目录的 `Images` 文件夹，导出的完整 JSON 备份包含仍在列表或垃圾堆中的截图，可在其他电脑恢复。自动快照引用同目录的图片文件，手动迁移整个数据目录时请一并复制 `Images`。截图移入垃圾堆后可恢复，清空垃圾堆也会保留图片文件供旧快照读取。
- 单击文件入口由 Windows 默认应用打开，文件夹由资源管理器打开；右键可打开所在文件夹、复制路径、修改名称或重新关联。找不到文件时显示重新关联入口。删除入口只删除记录并进入垃圾堆，原文件保留；重启、删除恢复及完整备份保留路径和名称。备份不包含原文件，文件搬家、换电脑或临时文件被清理后需重新关联。
- 垃圾堆合计保留最近删除的 10 条待办／常用内容，通过“待办／常用内容”二级标签切换显示；支持确认后清空垃圾堆。恢复的待办回到未完成列表，清空不改变现有待办、卡片、完成历史或重复任务的删除记录。
- 完成历史按主待办的完成日期筛选。主待办完成后，历史会记录当时的子待办结构，并在已勾选的子项右侧显示它实际完成的日期，例如 `2026-10-1`。旧版没有保存子项日期的记录会留空。删除待办不会删除独立的完成记录，取消主待办勾选会撤回对应的本次完成记录。
- 设置是独立窗口，保留开机自启动、系统托盘、跟随系统／浅色／深色主题及显示器选择。打开或再次呼出设置时，在当前工作应用所在显示器的工作区中央显示，避开任务栏并适配缩放；会在浮窗或托盘抢焦点前记住工作应用，不再围绕待办浮窗居中。从托盘打开设置不展开右侧浮窗，设置与浮窗没有窗口归属联动；保存设置、关闭或再次呼出设置也不主动展开浮窗。
- 设置的五个页面使用统一页头和紧凑的分组列表。宽窗口使用左侧导航，窄窗口使用顶部标签。备份、恢复和导入操作位于各项右侧，浮窗行为的保存按钮固定在页底。
- 设置中的“恢复默认窗口大小”会恢复主浮窗默认宽高和两张卡片的默认高度，保留内容、窗口位置、折叠状态、主题及其他设置，不弹成功提示。
- 待办与已完成条目共用同一套两列对齐：左侧先保留 4 像素留白，接着放置 16 像素状态标记，间隔 8 像素后显示标题，不再为隐藏的拖动把手留空。勾号使用圆头、圆角连接的几何线条，勾选后只显示勾线，不显示底框或白底。悬停使用中文优先字体的 Bold 字重、独立的文字与背景强调色，字号保持不变；“今日已完成”的箭头、勾选框和标题仍保持对齐。
- 日常任务、设置和编辑窗口仅保留关闭按钮，不提供最小化／最大化。再次打开已有日常任务或设置窗口时，会先恢复为正常状态再前置；最小化子窗口不会永久阻止主浮窗自动收起。
- 输入框内边距只应用一次，避免固定高度内重复挤压文字；待办／常用内容输入框左右内距为 8 像素，日常任务输入框左右为 6 像素。两张卡片标题使用中文优先字体、20 像素行高及底部余量，并启用布局像素取整。
- 日常任务表单统一使用 34 像素高的任务输入框、频率选择和日期选择，标签与两列控件基线对齐；星期选项等宽排列。设置、历史筛选和编辑窗口使用相同的字段间距与标签样式。
- 待办、常用内容和输入框右键菜单，以及托盘图标菜单均使用圆角、中性灰悬停和实时主题配色。输入框菜单保留剪切、复制、粘贴、全选及原快捷键。下拉箭头使用无底色的几何线条，悬停提示和日期弹层跟随主题。
- 托盘菜单按确认的深浅色样式实现，并略微收紧为 192 像素宽、32 像素行高、6 像素外侧留白，文字和图标大小保持不变；外圆角 12 像素、行高亮圆角 7 像素。四行统一点击宽度，高亮覆盖整行。左侧为随 DPI 绘制的窗口、日历、设置和退出线条图标，图标与文字垂直居中；退出前单独分隔。明确设置行尺寸与外侧留白，避免原生菜单重新计算内边距后只高亮文字附近。保留原生方向键选择、Enter 执行、Esc 和外部点击关闭；各尺寸随系统缩放调整，主题实时切换。
- 正常运行期间的确认和错误提示使用应用主题，关闭或取消不执行确认操作；启动尚未完成、主题资源不可用时保留系统提示框作为兜底。

已移除自动剪贴板监听、剪贴板图片缓存、中文 `vv` 短语触发、旧版通用键盘监听及鼠标穿透。底部没有浏览器式保存状态栏。

主浮窗最外层的滚动条浮在右侧留白内，不占内容宽度。滚动或指向右侧时显示细滑块，拖动时稍加粗，停止操作后淡出。待办列表、常用内容、设置、编辑框和下拉列表使用无边框透明轨道和圆润细滑块。深色主题使用深灰滑块，切换主题时实时更新。参考 [WPF UI ScrollBar](https://github.com/lepoco/wpfui/blob/main/src/Wpf.Ui/Controls/ScrollBar/ScrollBar.xaml) 的圆角滑块与透明轨道思路，使用项目自身 WPF 模板实现，无新增外部控件依赖。

## 配色

浅色使用白色主背景，深色使用 `#111111` 黑色主背景；卡片、边框、文字与控件使用中性灰，主要按钮自动匹配深浅文字。默认跟随 Windows 外观，也可在设置中手动选择。

色阶参考 [Radix Colors Gray](https://github.com/radix-ui/colors)；背景／前景成对的主题令牌参考 [shadcn/ui](https://github.com/shadcn-ui/ui)。配色调整不改变用户数据目录或格式。下拉框统一使用圆角、留白箭头与短暂展开动效；日历支持键盘方向键、PageUp／PageDown 换月、Esc 关闭。Windows 关闭动画时，软件也会禁用这类控件动效。

控件交互参考 [WPF UI](https://github.com/lepoco/wpfui) 与 [shadcn/ui Select](https://github.com/shadcn-ui/ui/blob/main/apps/v4/registry/new-york-v4/ui/select.tsx)，使用当前项目的 WPF 控件实现。输入框的圆角、留白和聚焦反馈参考 [WPF UI TextBox](https://github.com/lepoco/wpfui/blob/main/src/Wpf.Ui/Controls/TextBox/TextBox.xaml)，拖动区域与浮窗交互参考 [ModernFlyouts](https://github.com/ModernFlyouts-Community/ModernFlyouts)。

菜单和下拉控件参考 [WPF UI ContextMenu](https://github.com/lepoco/wpfui/blob/main/src/Wpf.Ui/Controls/ContextMenu/ContextMenu.xaml) 与 [WPF UI ComboBox](https://github.com/lepoco/wpfui/blob/main/src/Wpf.Ui/Controls/ComboBox/ComboBox.xaml) 的动态主题资源、圆角与间距。托盘继续使用原生 Windows Forms 菜单处理焦点、键盘和外部点击关闭，自定义绘制共享 WPF 主题色，无新增外部控件依赖。

## 更新软件与数据保留

**用户数据固定保存在 `%LOCALAPPDATA%\WinKit\`，与程序名称、程序文件夹和版本号无关。为兼容旧版已有数据，改名后继续使用此目录，无需手动迁移。**

后续更新：退出旧版 → 解压新版到任意程序目录 → 运行新的 `Levitation.exe`。不要删除 Windows 用户目录中的 WinKit 数据文件夹。已有 WinKit 开机启动项会在首次运行后迁移为 Levitation，保留原来的启用状态。启动时若已经启用开机自启，程序会同步更新该启动项的 EXE 路径。

数据管理入口：**设置 → 数据与备份**。

| 文件 | 用途 |
| --- | --- |
| `state.json` | 待办、完成历史、日常安排、常用内容、垃圾堆及设置 |
| `state.previous.json` | 上一个成功保存的有效版本 |
| `Backups/YYYY-MM-DD.json` | 修改前的每日快照，保留最近 14 份 |
| `before-restore-*.json` | 手动恢复备份前自动保存的完整数据，可从同一恢复入口还原 |
| `state.corrupt-*.json` | 从有效备份恢复后，保留的损坏主文件 |
| `crash.log` | 操作异常日志 |
| `state.lock` | 防止多个进程同时写入 |

每次修改先将完整候选数据写到同目录的临时文件并强制刷盘，成功后原子替换主文件；写入失败时不发布新的内存状态。读取失败时尝试有效备份；主文件与备份均无效时停止启动，避免生成空数据覆盖原文件。数据格式带 `schemaVersion`，较旧程序遇到较新格式会拒绝覆盖；兼容格式中未知的可选字段会保留。

自动备份与数据在同一块磁盘中；换电脑或保存独立副本时，使用“导出完整备份”。恢复前会展示条目数并要求确认，且自动保留恢复前的数据。数据与完成历史没有按天数自动清理。

后续开发需保持这一用户数据路径及已有记录的 ID 稳定。新增可选字段应提供兼容默认值；若调整格式版本，必须先实现旧格式迁移并保留迁移前副本，不能以“加载失败后重置”为升级方式。

### 从旧版 2.x 迁移

- 新版 EXE 所在目录若包含旧 `Data`，且用户目录尚无主数据，首次启动自动导入。
- 若新版放在其他目录，使用“导入旧版 Data 文件夹”选择旧文件夹。
- 导入 `todos.jsonl` 为待办、`recycle_bin.jsonl` 为完成历史，`phrases.jsonl`（或 `quick_phrases.jsonl`）为常用内容。
- 原文件不改动，相同来源不重复导入；发现损坏行会中止整次导入，不会悄悄丢掉那一行。
- 旧自动剪贴板文件及图片仍留在原目录，不自动转换为手动常用内容。
- 备份迁移仅在当前 Windows 用户内自动关联；换 Windows 账户或换电脑需要导出／恢复。

## 开发与构建

目标：Windows 10/11，.NET 8；WPF 原生界面，系统托盘使用 Windows Forms。核心业务层不依赖 Windows，可在 macOS/Linux 检查。

```sh
# 核心数据和调度检查（无需第三方测试包）
dotnet run --project Tests/Levitation.Core.Checks.csproj -c Release

# 编译（已启用非 Windows 系统的 Windows targeting）
dotnet build Levitation.csproj -c Release

# 自带运行库的 Windows x64 版本
dotnet publish Levitation.csproj -c Release -r win-x64 --self-contained true -o Publish/win-x64

# 如需 Windows ARM64 原生版本，将 RID 改为 win-arm64
```

GitHub Actions 的 `Windows build` 会运行核心检查、构建独立版本，并上传 ZIP。

Levitation 当前使用 `0.x.y` 预览版本号。发布时在 [Directory.Build.props](Directory.Build.props) 更新一次版本号，程序、Windows 清单和构建包名称会同步使用它。提交通过检查后，为对应提交创建 `v<版本号>` 标签，例如 `v0.1.1`。从标签触发构建时，工作流会检查标签与程序版本一致。公开发布时从对应标签创建 GitHub 预发布并附上该次构建的 ZIP。

| 目录 | 职责 |
| --- | --- |
| `Core` | 数据模型、持久化、迁移、日常任务和完成历史 |
| `Desktop` | 原生浮窗、设置与编辑窗口、托盘、自启和显示器交互 |
| `Tests` | 重启、读写失败、备份恢复、格式升级保护、迁移和调度检查 |
| `.github/workflows` | Windows 构建和交付产物 |

当前开发环境为 macOS。交叉编译和核心检查可以在这里完成；鼠标停靠、多屏 DPI、托盘、自启与原生界面仍需在 Windows 上进行实际验收。
